# 知識工廠自動化系統

一套「複製 YouTube 網址 → 雙擊執行 → 自動產生 Obsidian 筆記」的個人知識管理小工具：自動抓字幕，交給 Gemini 整理成繁體中文的結構化 Markdown 筆記，寫進你指定的資料夾（例如 Obsidian 筆記庫或雲端硬碟）。

> 🆕 第一次使用？請看 [SETUP.md](SETUP.md)，內有 **Windows 原生** 與 **WSL** 兩種安裝方式。

---

## 一、運作流程

```
[ 步驟 1 ] 瀏覽器複製網址 (Ctrl + C)
      │
      ▼
[ 步驟 2 ] 雙擊啟動器 (.bat)，或在終端機執行 python sync_agent.py [網址]
      │
      ├─► 讀取剪貼簿（或命令列帶入的網址）
      ├─► 安全檢查（網址格式、輸出資料夾是否可寫入）
      ├─► 取得影片原標題、頻道、發布日與 YouTube 字幕
      └─► 送交 Gemini 整理成繁中結構化筆記
      │
      ▼
[ 步驟 3 ] 寫入你設定的 OUTPUT_DIR（可直接是 Obsidian 筆記庫內的資料夾）
      │
      ▼
[ 步驟 4 ]（選用）網頁版 NotebookLM 勾選新檔案，開始深度研究
```

## 二、專案結構

```
KnowledgeFactory/
├── sync_agent.py                  # 主程式：抓字幕 → Gemini 整理 → 寫入筆記
├── requirements.txt               # 鎖定版本的套件清單
├── .env.example                   # 設定範本（複製成 .env 後填入）
├── .env                           # 你自己的設定：API Key、輸出資料夾（機密，不會上傳）
├── launchers/
│   ├── start_windows.bat.example  # Windows 原生：雙擊啟動器範本
│   └── start_wsl.bat.example      # 從 Windows 雙擊、在 WSL 內執行的啟動器範本
├── .venv/                         # Python 虛擬環境（自行建立，不會上傳）
├── README.md
└── SETUP.md
```

個人化的內容（API Key、輸出資料夾）全部放在 `.env`，程式本身不含任何個人路徑。

### `.env` 設定項目

| 變數 | 必填 | 說明 |
|---|---|---|
| `GEMINI_API_KEY` | 是 | Gemini API Key |
| `OUTPUT_DIR` | 是 | 筆記輸出資料夾。建議指到 Google Drive 資料夾。Windows 例：`G:\我的雲端硬碟\Notes\YouTube_Notes`；WSL 例：`/mnt/g/我的雲端硬碟/Notes/YouTube_Notes`（需先掛載 G:） |
| `GEMINI_MODEL` | 否 | 指定模型，預設 `gemini-3.5-flash` |

若輸出到 Google Drive 之類的雲端硬碟，同步通常有 **5～30 秒延遲**，Obsidian 不會「秒級」更新，等個十幾秒再重新整理即可。

## 三、日常使用

### 3.1 YouTube 影片轉筆記

1. 在 YouTube 看到想收藏的影片，複製網址（`Ctrl + C`）。
2. 雙擊你的啟動器（見 [SETUP.md](SETUP.md)），或在專案資料夾執行：
   ```bash
   python sync_agent.py                    # 讀取剪貼簿上的網址
   python sync_agent.py "https://www.youtube.com/watch?v=..."   # 直接帶網址
   ```
   （WSL 請用 `.venv/bin/python sync_agent.py`，Windows 請用 `.venv\Scripts\python.exe sync_agent.py`。）
3. 程式會自動：
   - 驗證網址是否為合法 YouTube 網址，並確認輸出資料夾可用
   - 解析影片 ID，並取得**影片原標題、頻道名稱**（YouTube oEmbed，不需要 API Key）與**發布日**（解析影片頁面）
   - 依序嘗試抓取中文 → 英文 → 任何可用語言的字幕（找不到中英字幕時會自動 fallback，並交給 Gemini 翻譯整理）
   - 將逐字稿送交 Gemini，產出結構化的 Markdown 筆記
   - 寫入 `OUTPUT_DIR`，**檔名直接使用影片原標題**（例如 `<影片原標題>.md`），開頭帶有程式產生的屬性區塊
4. 看到「🎉 大功告成」代表完成（用啟動器時 5 秒後自動關閉）；失敗時視窗會停留並顯示錯誤訊息。

### 3.2 匯入 NotebookLM 進行深度研究（選用）

1. 打開網頁版 [NotebookLM](https://notebooklm.google.com)，進入你的知識庫筆記本。
2. 點擊「新增來源」→「Google 雲端硬碟」，勾選剛產出的新筆記。
3. 開始對 AI 進行跨筆記的深度提問與研究。

> 這一步刻意保留為**手動操作**：NotebookLM 目前沒有公開 API 可供腳本匯入，手動勾選也能讓你在送進研究庫前先確認筆記品質。

## 四、模型與版本鎖定

- 預設使用 **`gemini-3.5-flash`**，並在程式裡明確指定，不依賴套件的預設值。
- `requirements.txt` 鎖定 `google-antigravity==0.1.5`。原因：該套件升級後**預設模型會跟著改變**（實測 0.1.22 的預設是 `gemini-3.8-flash`，回應時間從約 45 秒變成 5 分鐘以上，筆記格式也不同）。要換模型時，在 `.env` 設定 `GEMINI_MODEL` 即可。
- Gemini 免費方案有**每日請求上限**（實測約 20 次／天，以 Google 當下公告為準）。額度用盡時程式會直接提示，不會白白重試。

### 筆記輸出的格式要求

提示詞固定了筆記的風格，讓每部影片的筆記長得一致（工整、純文字、有層級與序號）：

| 項目 | 規則 |
|---|---|
| 語言 | 繁體中文（台灣） |
| 標題層級與序號 | 大主題 `## 一、`、中主題 `### (一)`、小主題 `#### 1.`、第四層 `##### (1)`，最多四層，序號依序編、不跳號 |
| 裝飾 | 不使用 emoji 與裝飾符號，也不使用 callout（`> [!…]`）與 mermaid 流程圖 |
| 內文 | 以條列為主，條列最多兩層；粗體只用在關鍵詞（程式會修正 `**「…」**` 這類在中文不會變粗體的寫法）；表格只在比較多組數字時才使用 |
| 固定結構 | 第一個大主題是「一、內容摘要」（3～5 句），最後一個大主題是「結論與重點整理」 |
| 不輸出的內容 | `#` 一級標題（標題由檔名提供）、開場白、結尾說明、工作報告、YAML 屬性區塊 |
| 標籤 | 在筆記最後一行以「標籤：a, b, c」提供，由程式取出放進屬性 |
| 檔案工具 | 不得呼叫任何檔案工具（檔案寫入完全由 Python 處理） |

提示詞只能降低模型亂加格式的機率，所以程式在寫入前還有一道保險：移除殘留的 emoji（程式碼區塊內不動；箭頭、★ 這類表達內容的符號會保留），並把所有標題的序號統一重編成上述格式，因此不論模型怎麼寫，標題序號都會一致。

筆記的標題就是**檔名（影片原標題）**。Obsidian 會把檔名顯示在筆記最上方，所以內文不再放 `#` 一級標題，直接從 `##` 段落開始；若模型仍自己加了 `#` 一級標題，程式會把它移除，避免標題重複。

- 檔名會去掉不能使用的字元（`\ / : * ? " < > |`），並限制長度（約 100 字、240 bytes 內），避開 Windows 路徑長度上限。
- 取不到影片標題時（網路問題，或影片為私人／非公開），檔名改用 `YT_<影片ID>.md`，並在終端機顯示警告。
- 同一支影片重跑，會覆蓋同一個檔案（程式會先提示）；不同影片若標題完全相同也會互相覆蓋。

### 筆記開頭的屬性區塊

筆記最前面有一個由**程式**產生的 Obsidian 屬性區塊（格式比照 Obsidian Web Clipper，讓剪藏與 YouTube 筆記可以用同一套屬性搜尋）：

| 屬性 | 內容 |
|---|---|
| `source` | 影片網址 |
| `author` | 頻道名稱，以雙向連結寫成 `[[頻道名稱]]` |
| `published` | 影片發布日（取不到就省略） |
| `created` | **製作這份筆記的日期**（不是影片發布日） |
| `tags` | **由模型依影片內容決定**（3～6 個，以繁體中文為主，例如 `品牌策略`、`日本戶外`）；模型沒有提供時省略這個屬性 |

屬性區塊的格式由程式固定產生，所以每份筆記一致；只有 `tags` 的內容由模型依影片內容決定（提示詞要求模型在筆記最後一行以「標籤：a, b, c」提供，程式取出後放進屬性並把那一行從內文移除）。若模型仍自己輸出屬性區塊，程式會把它移除，避免重複。

寫入前，程式會自動去除模型偶爾加上的外層 ` ```markdown ... ``` ` 程式碼圍欄（Obsidian 會把被圍欄包住的整篇筆記顯示成程式碼）；筆記內部本來就有的程式碼區塊（例如 mermaid）不受影響。

## 五、疑難排解

| 錯誤訊息 / 現象 | 可能原因 | 處理方式 |
|---|---|---|
| `❌ 【設定不完整】尚未設定 OUTPUT_DIR` | `.env` 沒有設定輸出資料夾 | 在 `.env` 加入 `OUTPUT_DIR=...`（見上方設定表） |
| `⚠️ 無法取得影片標題，檔名改用 YT_<影片ID>.md` | 查詢 YouTube oEmbed 失敗（網路問題，或影片為私人／非公開） | 不影響筆記內容；之後可手動把檔名改成影片標題，或確認網路後重跑 |
| 筆記屬性缺少 `author` 或 `published` | 查詢 YouTube oEmbed 或解析影片頁面失敗（網路問題、影片限制） | 不影響內容；缺的屬性會被省略，可之後手動補上 |
| 筆記屬性沒有 `tags` | 模型沒有依提示詞在最後一行輸出「標籤：…」 | 不影響內容；重跑一次通常就有，或之後手動補標籤 |
| 筆記裡出現 emoji，或標題序號格式不統一 | 模型沒有完全照提示詞輸出（舊版程式產生的筆記也會有） | 新版寫入前會自動移除 emoji 並重編標題序號；舊筆記可以用同樣的處理手動整理 |
| `❌ 【設定錯誤】在 WSL 內 OUTPUT_DIR 不能用 Windows 路徑` | 在 WSL 裡把路徑寫成 `G:\...` | 改成 `/mnt/g/...` 的寫法 |
| `❌ 【安全中斷】/mnt/g 尚未掛載` | WSL 內輸出路徑所在的磁碟或雲端硬碟沒有掛載。沒掛載時它只是 WSL 內的空資料夾，直接寫入會寫到錯的地方，所以程式先中止 | 確認磁碟或雲端硬碟已啟動，執行 `sudo mount -a`（掛載設定見 [SETUP.md](SETUP.md)） |
| `'YouTubeTranscriptApi' has no attribute 'list_transcripts'` | 套件版本為 1.x，API 已改版 | 確認 `sync_agent.py` 為最新版本（使用 `.list()`），並用 `pip install -r requirements.txt` 安裝鎖定的版本 |
| 抓字幕失敗，但影片明明有字幕 | YouTube 暫時阻擋該 IP、或字幕語言非中英文 | 稍後重試；冷門語言程式會自動 fallback 並交給 Gemini 翻譯 |
| `model produced an invalid tool call`、`is not a valid artifact path` | 模型嘗試呼叫 Antigravity 內建的 `create_file` 工具，Antigravity 規定工具產生的檔案只能寫進 `~/.gemini/antigravity/brain/<session_id>/` 沙盒 | 已在提示詞中明確禁止模型呼叫任何檔案工具，檔案寫入完全交由 Python 腳本處理 |
| `503` / `high demand` / `UNAVAILABLE` | Google 後端模型當下流量過大，屬暫時性問題 | 程式會自動以 8s/16s/32s/64s 間隔重試最多 4 次；仍失敗請等幾分鐘後再執行 |
| 速率限制相關錯誤 | 短時間內處理過多影片 | 同上，內建自動重試；仍失敗請間隔幾分鐘再執行 |
| `RESOURCE_EXHAUSTED`、訊息含 `PerDay` | Gemini 免費方案**每日**額度已用盡，重試無效 | 程式會偵測並直接放棄重試；等隔天額度重置，或前往 https://ai.dev/rate-limit 查看用量、升級方案 |
| Obsidian 沒看到新筆記 | 雲端硬碟同步延遲 | 等 10～30 秒後重新整理 Obsidian |
| Obsidian 整篇筆記顯示成灰底程式碼 | 筆記被包在 ` ```markdown ` 圍欄裡（舊版程式產生的檔案） | 新版寫入前會自動去除；舊筆記請手動刪掉第一行與最後的 ` ``` ` |
| `ModuleNotFoundError: No module named 'dotenv'`（或其他已安裝的套件） | 沒有使用專案的虛擬環境執行 | 確認用 `.venv` 內的 Python 執行，必要時重新 `pip install -r requirements.txt` |
| 筆記裡看到字面的 `**` | 粗體符號內側緊貼標點、外側緊貼中文，Markdown 不判定為粗體 | 新筆記程式會自動修正；舊筆記可將 `**「A」**的` 改成 `「**A**」的` |
| 雙擊 `.bat` 後跳出亂碼、顯示「不是內部或外部命令」 | `.bat` 含中文字，在繁體中文 Windows 下 `cmd.exe` 會誤判位元組 | 啟動器範本維持**純 ASCII**，不要在 `.bat` 裡加中文 |
| 視窗一閃就消失，看不到錯誤 | 啟動器沒有失敗暫停機制 | 使用 `launchers/` 內的範本（含 `if %errorlevel% neq 0 pause`） |

## 六、安全與隱私須知

- `.env` 內含個人 API Key，外洩後他人可能用你的額度呼叫 Gemini，產生非預期費用或濫用紀錄。**絕對不要**上傳到 GitHub、雲端硬碟，或包進要分享的壓縮檔。
- 本系統不會將任何資料上傳到除 Gemini API 與你自己設定的輸出資料夾（及其雲端同步）之外的服務。
